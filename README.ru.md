# Транспорты OpenFlux

Официальные транспорты [OpenFlux](https://github.com/p1neappleXpress/OpenFlux) как
подписанные версионные JS-пакеты, по каталогу на каждый. Приложения кладут в сборку
их снимок, обновляют на месте (вкладка «Транспорты») и показывают каталог. Здесь
исходники и выпуск. Свой транспорт делайте из форка
[OpenFluxTransportTemplate](https://github.com/p1neappleXpress/OpenFluxTransportTemplate).

## Состав

```
transports/<id>/main.js         транспорт (собирается бандлом: может require("../../lib/..."))
transports/<id>/manifest.json   id, name, version, wire, api, update (подписывается вместе с пакетом)
transports/<id>/setup.html      страница мастера настройки: пишется и смотрится в браузере (необязательна)
transports/<id>/setup_html.js   она же строкой JS, её подключает main.js (делает scripts/embed-html.sh)
lib/                            общие модули (капча, клиент MAX)
index.json                      каталог, который показывают приложения
scripts/build.sh                бандл + упаковка + подпись одного транспорта
scripts/embed-html.sh           setup.html -> setup_html.js
```

`name` и `version` в `manifest.json` должны совпадать с `info()` самого скрипта
(`scriptsign pack` не пропустит расхождение). `wire` — поколение формата обмена:
клиент и нода запускают один транспорт, поэтому новый `wire` ломает совместимость,
и приложения ждут подтверждения пользователя.

## Выпуск

Тег `<id>-v<версия>`: `yandex-v1.2.0` → канал stable, `yandex-v1.3.0-beta.1` → канал nightly
(pre-release). CI соберёт только этот транспорт, подпишет секретом `SIGNING_KEY` (ключ
выпуска OpenFlux), выложит `<id>-<версия>.flux` в релиз и запишет в `<id>/update.json` на
ветке `updates` — его опрашивают установленные приложения. Стабильный выпуск не стирает
запись nightly. Проверка при каждом push собирает все транспорты временным ключом.

## Ключи

Транспорт «официальный», если подпись сходится с одним из ключей списка `officialKeys` в
ядре (`transport/script/trust.go`). Смена ключа — два релиза ядра: первый добавляет новый
публичный ключ в список, второй (когда он у большинства) переключает `SIGNING_KEY`.
Обновления официальных транспортов, подписанные другим официальным ключом, принимаются, а
установка перепривязывается к нему. Утёкший ключ убирают из списка релизом ядра.
